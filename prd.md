# PRD: «Траектория» — калькулятор нормы калорий по месяцам

**Статус:** реализовано (v1.1 — добавлен экспорт/печать)
**Тип продукта:** standalone веб-приложение (один HTML-файл, без бэкенда)
**Файл:** `traektoriya.html`

---

## 1. Проблема

Стандартные калькуляторы калорий дают одну статичную цифру на основе текущего веса и не учитывают, что при движении к целевому весу меняется и сам обмен веществ (BMR). Из-за этого норма, рассчитанная на старте, к концу пути становится неточной — особенно при значительном изменении веса или длинном сроке (несколько месяцев).

## 2. Цель продукта

Дать человеку не «одну цифру», а **план**: норму калорий на каждый месяц пути от текущего веса к целевому, с пересчётом обмена веществ по мере движения, и предупредить, если темп изменения веса слишком агрессивен для здоровья.

## 3. Целевая аудитория

Человек, который:
- знает свой рост, вес, возраст и примерный уровень активности;
- хочет снизить, набрать или удержать вес за конкретный срок (месяцы);
- ищет ориентир по калориям, а не готовый диетический план от диетолога.

## 4. Пользовательский сценарий

1. Пользователь открывает файл в браузере (десктоп или мобильный, офлайн — кроме загрузки шрифтов).
2. Заполняет три блока: «О вас» (пол, возраст, рост, текущий вес), «Активность» (один из 5 уровней), «Цель» (целевой вес, срок в месяцах).
3. Нажимает «Построить траекторию».
4. Получает: сводку (BMR, поддерживающая норма, изменение веса, темп в неделю), ИМТ старт/цель, график веса, карточки нормы калорий по каждому месяцу, общие советы по питанию и разворачиваемую таблицу с полными цифрами.
5. При слишком агрессивном плане видит предупреждение с рекомендацией смягчить цель или увеличить срок.

## 5. Функциональные требования

### 5.1 Входные данные
| Поле | Диапазон | Обязательность |
|---|---|---|
| Пол | муж / жен | да |
| Возраст | 14–100 лет | да |
| Рост | 100–230 см | да |
| Текущий вес | 30–300 кг | да |
| Уровень активности | 1 из 5 (множитель 1.2–1.9) | да |
| Целевой вес | 30–300 кг | да |
| Срок | 1–36 месяцев | да |

Уровни активности (простая пятиступенчатая шкала, без детального дневника тренировок):
1. Минимальная (×1.2) — сидячая работа
2. Лёгкая (×1.375) — 1–3 тренировки/нед
3. Умеренная (×1.55) — 3–5 тренировок/нед
4. Высокая (×1.725) — 6–7 тренировок/нед
5. Очень высокая (×1.9) — физический труд + тренировки

### 5.2 Расчётная логика
- **BMR** — формула Миффлина–Сан Жеора.
- **TDEE (норма поддержания)** = BMR × коэффициент активности.
- **Траектория веса** — линейная интерполяция от текущего к целевому весу с равным шагом на каждый из N месяцев.
- **Пересчёт по месяцам** — для каждого месяца BMR и TDEE считаются заново от среднего веса за этот месяц (а не от стартового), что и даёт точность на длинных сроках.
- **Суточный дефицит/профицит** = (изменение веса за месяц × 7700 ккал/кг) / ~30.44 дня.
- **Норма калорий на месяц** = TDEE месяца + суточный дефицит/профицит.

### 5.3 Ограничения безопасности
- Норма калорий не показывается ниже безопасного минимума: **1500 ккал** (муж) / **1200 ккал** (жен) — если расчёт уходит ниже, отображается зафиксированное минимальное значение с пометкой.
- Если недельный темp изменения веса превышает **~1% веса тела** или суточный дефицит/профицит больше **1000 ккал**, месяц помечается как «агрессивный темп».
- При наличии таких месяцев над планом показывается предупреждающий баннер с рекомендацией увеличить срок или смягчить цель и обратиться к врачу.

### 5.4 Вывод
- Сводная панель: BMR сейчас, норма поддержания, общее изменение веса, средний темп в неделю.
- Чипы ИМТ (старт и цель) с категорией.
- SVG-график веса по месяцам (анимированная линия + точки-вехи).
- Горизонтальная лента карточек по месяцам: норма ккал/день, вес к концу месяца, дельта к поддержанию, флаг предупреждения (если есть).
- Блок общих советов по питанию (см. 5.5).
- Разворачиваемая таблица с полными цифрами по каждому месяцу (для тех, кому нужны точные значения).

### 5.5 Общие советы по питанию
Дополняют цифру калорий немедицинскими, общими ориентирами:
- **Вода** — персонализировано от текущего веса (~30–35 мл/кг).
- **Белок** — персонализировано от целевого веса (диапазон г/день, с акцентом на сохранение мышечной массы при дефиците).
- **Клетчатка** — общий ориентир 25–30 г/день (не персонализировано).
- **Режим питания** — общая рекомендация по количеству и регулярности приёмов пищи.

Явно не входит: конкретные продукты/рецепты, детальный подсчёт БЖУ по приёмам пищи, персональные медицинские рекомендации.

### 5.6 Экспорт / печать
- Кнопка «Скачать / Печать · PDF» в блоке результатов запускает системную печать браузера (`window.print()`) — пользователь сохраняет как PDF через диалог печати или печатает на бумаге. Отдельная генерация PDF не используется — не требует внешних библиотек и работает офлайн.
- Перед печатью таблица по месяцам принудительно разворачивается, чтобы попасть в документ.
- В печатной версии скрываются форма ввода, декоративная шапка и сама кнопка экспорта; вместо них выводится компактная шапка с названием, датой формирования и сводкой введённых параметров (пол, возраст, рост, вес старт→цель, срок, активность) — печатный документ самодостаточен и понятен без формы.
- Лента карточек по месяцам в печати превращается из горизонтальной прокрутки в перенос по сетке (~3 в ряд), чтобы все месяцы попали на страницу.

## 6. Нефункциональные требования
- Один самодостаточный HTML-файл (CSS + JS инлайн), без сервера и без сборки.
- Работает офлайн, кроме загрузки веб-шрифтов (есть системные фолбэки).
- Отсутствие `localStorage`/`sessionStorage` — всё состояние только в памяти на время сессии, ничего не сохраняется между открытиями.
- Адаптивная вёрстка (мобильный / десктоп).
- Видимый фокус для клавиатурной навигации.
- Устойчивость к ошибкам: расчёт обёрнут в try/catch, чтобы сбой в отдельном узле (например, отрисовке графика) не «ронял» весь результат молча.

## 7. Вне рамок (out of scope v1)
- Учёт детальных тренировок (тип, длительность, интенсивность) — только 5-ступенчатый общий коэффициент активности.
- Персональный подбор продуктов, рецептов, меню.
- Подробная разбивка БЖУ по приёмам пищи.
- Сохранение истории / аккаунты / синхронизация между устройствами.
- Учёт возрастных изменений в ходе длинного плана (возраст считается неизменным на весь срок).
- Медицинские противопоказания и индивидуальные состояния здоровья.

## 8. Открытые вопросы / возможные доработки
- Нужна ли разбивка БЖУ в граммах по каждому приёму пищи, а не только суточный диапазон белка?
- Стоит ли учитывать нелинейную траекторию веса (быстрее в начале, медленнее к концу — как чаще бывает физиологически)?
